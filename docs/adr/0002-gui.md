# ADR 0002: GUI 확장 방식 — 로컬 웹 화면(Node 내장 http) 채택

- 상태: 제안(#9). 2026-10-26, 기준 `origin/main`. 사람 검토·병합 전입니다.
- 범위: CLI와 같은 공용 서비스(`packages/**`)를 호출하는 첫 GUI. 먼저 읽기 전용 흐름(작업 폴더·참고 폴더 선택 → 분석 → 미리보기·규칙 후보 확인)만 연결하고, 승인·실행 화면은 #8 `approvals.ts`와 #10–#12 `executor.ts`가 main에 들어온 뒤 연결합니다.
- 검증 수준: 이 ADR은 설계 결정입니다. 구현·검증 결과는 `docs/verification/ISSUE_9.md`에 따로 적습니다.

## 조건

- D10: CLI가 1차 인터페이스이고 GUI는 같은 계약·엔진·승인·실행 서비스를 쓰는 어댑터입니다. GUI는 CLI 출력이나 shell 문자열을 파싱하지 않습니다.
- 루트 `package.json`·lockfile에 의존성을 추가하지 않습니다. GUI는 `apps/desktop/` 자체 `package.json`·lockfile을 씁니다.
- 실행 권위(루트 제한·승인·파일 상태 재검증)는 공용 서비스에 있고, GUI 어댑터는 채널 요청자와 입력만 확인합니다.
- 해커톤 일정(11/5 제출)과 2인 팀. Windows/macOS 두 OS.

## 결정

1. 첫 GUI는 `apps/desktop/`의 **로컬 웹 화면**입니다. Node 프로세스가 `127.0.0.1`의 임의 포트에서 정적 화면과 JSON API를 제공하고 기본 브라우저로 엽니다. 핵심 로직은 `packages/**`의 공용 서비스를 같은 프로세스에서 호출합니다.
2. Electron은 후속 포장 방법으로 남깁니다. 화면(정적 HTML/JS)과 API 계약이 프레임워크에 묶이지 않게 해, 필요하면 같은 화면을 Electron `BrowserWindow`에서 열고 API를 IPC로 옮길 수 있게 합니다. Tauri는 TS 엔진 재사용이 어렵고 런타임이 둘이 되므로 채택하지 않습니다.
3. 대회의 "URL 직접 실행" 요구(D03)는 이 결정으로 충족되지 않습니다. `http://127.0.0.1:<port>`는 사용자의 컴퓨터에서만 열리는 주소입니다. 제출 URL은 #15에서 따로 정합니다.

## 보안 설계 (로컬 웹 화면의 위협과 대응)

위협: (a) 사용자가 연 다른 웹사이트가 `127.0.0.1:<port>`로 요청(CSRF), (b) DNS rebinding으로 다른 사이트가 같은 출처처럼 접근, (c) 같은 컴퓨터의 다른 프로세스·사용자가 포트에 접속, (d) 화면이 보낸 임의 경로·위조 ID로 루트 밖 접근, (e) 화면에 주입된 스크립트.

| 대응 | 내용 |
| --- | --- |
| 바인딩 | `127.0.0.1`만, 포트는 OS가 고른 임의 포트. `0.0.0.0`·IPv6 와일드카드 금지 |
| 실행별 비밀 토큰 | 시작마다 256비트 난수. 브라우저는 `http://127.0.0.1:<port>/#t=<토큰>`으로 열고, 화면은 fragment(서버·로그로 전송되지 않음)에서 읽어 `sessionStorage`에 두고 주소에서 지움. 모든 API 요청은 `X-AFO-Token` 헤더 필수, 상수 시간 비교 |
| 요청자 확인 | `Host`가 정확히 `127.0.0.1:<port>`가 아니면 거부(DNS rebinding). `Origin`이 있으면 정확히 `http://127.0.0.1:<port>`여야 함. API는 `POST` + `Content-Type: application/json`만. CORS 헤더를 보내지 않으므로 다른 출처의 사용자 지정 헤더 요청은 preflight에서 막힘 |
| 입력 검증 | 채널마다 `z.strictObject` 스키마, 본문 크기 한도, 알 수 없는 필드 거부. 경로를 직접 받는 채널은 "작업 폴더 지정"과 "참고 폴더 지정" 둘뿐이며 공용 `issueRootGrant`/`issueReferenceGrant` 정책(OS 폴더·홈·디스크 루트·개발 프로젝트·링크 거부)을 그대로 거침. 나머지 채널은 서버가 발급한 grant ID만 받고, 모르는 ID·위조 grant·다른 scope는 거부 |
| 화면 격리 | CSP `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`. 화면은 파일명을 `textContent`로만 넣고 `innerHTML`을 쓰지 않음 |
| 브라우저 열기 | macOS `/usr/bin/open <url>`, Windows `explorer.exe <url>`을 `execFile`(shell 없음)로 실행. `--no-open`이면 터미널에 주소만 출력 |
| 종료 | 터미널 Ctrl+C로 서버 종료. 서버는 상태 폴더 외에는 아무것도 쓰지 않음(읽기 전용 흐름) |

남는 위험(수용·문서화): 토큰이 든 URL은 브라우저 열기 명령의 인수로 잠깐 존재해 같은 컴퓨터의 다른 사용자가 프로세스 목록에서 볼 수 있습니다. 브라우저 확장 프로그램은 탭 내용을 읽을 수 있습니다. 같은 사용자 권한의 악성 프로세스는 이 설계로 막을 수 없습니다(CLI도 같음). 실행 화면을 연결할 때 승인 코드 입력은 CLI와 같은 공용 서비스 검사를 거치며, GUI 전용 우회나 기본 동의를 만들지 않습니다.

## 화면 흐름 (첫 단계: 읽기 전용)

작업 폴더 선택(대화상자 또는 경로 입력) → 참고 폴더 선택(건너뛰기 가능) → 분석(진행률·취소) → 미리보기: 이동 제안/유지/검토, 중복 후보(남길 파일 제안, 논리 크기는 확보량 아님), 큰 파일, 제외·오류 → 참고 규칙 후보 확인(근거 표시, 선택한 규칙만 확인; 저장은 #18 저장소가 main에 들어온 뒤 연결).
"실행" 버튼은 #8/#10–#12가 연결되기 전까지 표시하지 않습니다(동작하지 않는 화면으로 기능이 있는 것처럼 보이지 않게).

## 검증 계획

- 서버 API 단위·부정 검사(`apps/desktop` 자체 `npm test`): 토큰 없음/틀림, `Host`/`Origin` 위조, 다른 메서드·Content-Type, 큰 본문, 알 수 없는 필드, 모르는 grant ID, OS 폴더·홈·링크·상대 경로 입력 거부, 분석 결과가 CLI(`analyzeRoot`)와 같은 계약.
- 실제 화면: 합성 temp 폴더로 서버를 띄우고 실제 브라우저에서 렌더·입력·클릭·결과 표시를 확인. 분석 전후 합성 폴더 manifest가 같은지(읽기 전용) 대조. mock 화면은 검증으로 보고하지 않습니다.
- Windows: 구현만, 미검증(CI 대기 또는 실물 필요). 폴더 대화상자는 OS별 실물 확인이 필요합니다.
