# 문서·사진·복합 규칙 정리

v0.5.0에서 추가한 분석과 충돌 해결 기능입니다. CLI와 `afo gui`는 같은 분석·계획·승인·파일 실행 서비스를 사용합니다. 파일 이동·삭제는 미리보기만으로 실행하지 않으며 기존 배치 승인과 실행 직전 검사를 유지합니다.

## 이름 충돌과 개별 수정

기본값은 충돌을 검토 대상으로 남기는 방식입니다. `--conflicts keep-both`를 선택하면 기존·예정된 목적지와 겹치지 않는 `파일 (1).확장자`, `파일 (2).확장자`를 결정적으로 제안합니다. 계획 이후 누군가 같은 이름을 만들면 실행기가 덮어쓰지 않고 해당 작업을 거부합니다.

```sh
afo preview "/작업/폴더" --conflicts keep-both
afo plan "/작업/폴더" --conflicts keep-both
afo preview "/작업/폴더" --rename "보고서.pdf=보고서 최종.pdf"
afo preview "/작업/폴더" --skip "보관할 원본.pdf"
```

`--skip`은 이번 분석의 본문·사진 추가 읽기와 이동·삭제에서 해당 파일을 제외합니다. 참고 파일 보호가 우선이며 건너뛴 파일을 `--delete-file`로 동시에 선택하면 거부합니다. `--rename`에는 경로·숨김 이름·예약 이름을 넣을 수 없습니다. 분류가 불명확한 파일을 이름 변경하려면 `--move`로 목적지도 명시합니다.

화면에서는 추가 옵션의 ‘두 파일 모두 보관’을 선택하거나 파일별 ‘이번엔 건너뛰기’, 새 이름·목적지 수정으로 제안을 바꿉니다. 이 단계는 사용자 파일을 바꾸지 않습니다. 같은 옵션으로 계획을 만들고 작업 목록을 확인해 실행해야 합니다. 정리 이동은 `afo undo`로 원래 경로·이름으로 되돌립니다.

## 복합 규칙

‘개인 규칙’ 화면에서 규칙 이름, 작업 루트 안의 목적지, 우선순위와 조건을 편집합니다. 모든 조건(AND) 또는 하나 이상의 조건(OR)을 선택할 수 있습니다.

- 파일 이름·상대 경로·확장자: 포함, 미포함, 같음, 시작, 끝
- 크기: 바이트 기준 이상·이하
- 수정일: 이 컴퓨터의 달력 날짜 기준으로 지정일보다 이전·이후. 해당 날짜는 포함하지 않습니다.

명시적 이번 수정·저장한 사용자 수정이 먼저 적용됩니다. 그다음 기존 개인 폴더 보존, 높은 우선순위의 복합 규칙, 참고 폴더 규칙, 선택한 촬영일/내용 분석, 기본 확장자 분류 순서입니다. 같은 우선순위가 서로 다른 목적지를 고르면 임의로 선택하지 않고 검토 대상으로 남깁니다. 근거 없는 메타데이터를 0이나 1970년으로 추정해 조건을 맞추지 않습니다.

```sh
afo rules example > rule.json
# JSON의 name, targetDirectory, conditions 등을 원하는 조건으로 수정
afo rules add rule.json
afo rules list --json
afo rules test "물리_보고서.pdf" --size 12000 --modified 2026-11-05
afo rules edit rule-with-existing-id.json
afo rules enable <규칙ID>
afo rules disable <규칙ID>
afo rules remove <복합규칙ID>
```

가상 입력 테스트는 실제 파일을 읽거나 실행한 증거가 아닙니다. 저장한 규칙을 실제 미리보기에서 다시 확인합니다. 규칙 저장·편집·삭제는 기존 프로필 잠금과 revision 검사를 사용하고, 변경 전 계획의 승인을 재사용하지 않습니다. 기존 참고 규칙과 사용자 수정을 보존하며 기존 v2 프로필을 읽습니다. 새 복합 규칙을 저장한 프로필은 구버전 앱에서 해석되지 않을 수 있으므로 앱을 내려서 실행하지 않는 것을 권장합니다.

## 문서 본문과 선택형 로컬 AI

```sh
afo formats
afo formats --json
afo formats --categories
afo preview "/작업/폴더" --content
afo preview "/작업/폴더" --content --ocr
afo preview "/작업/폴더" --content --ai-model <설치된-Ollama-모델>
```

- 텍스트·마크다운·코드·CSV/JSON/XML 등의 본문은 UTF-8, BOM 있는 UTF-16, EUC-KR로 읽습니다.
- PDF는 현재 Mozilla PDF.js의 텍스트 추출 API와 내장 문자표/글꼴을 사용합니다. PDF의 스크립트를 실행하지 않습니다.
- DOCX/DOCM/DOTX/DOTM, PPTX 계열, XLSX 계열, HWPX, ODT/ODP/ODS, EPUB은 압축 내부의 본문 XML/HTML을 추출합니다. 문서의 매크로를 실행하지 않습니다.
- RTF는 Unicode 제어어와 지원 문자표의 이스케이프를 해독합니다. FB2와 Flat ODF는 XML 텍스트를 읽습니다.
- 구형 바이너리 HWP·DOC·XLS·PPT, Pages/Keynote/Numbers 등은 **종류별 분류만** 제공하며 본문 추출은 지원하지 않습니다. 파일별로 이 사실을 표시합니다.
- 이미지·스캔 PDF의 OCR은 `--ocr`를 선택할 때 OS 기능을 사용합니다. macOS는 Vision/PDFKit, Windows는 Windows OCR/Imaging/PDF API를 사용합니다. OS 코덱·OCR 언어가 없으면 실패 이유를 표시합니다.

본문의 물리·화학·수학·생명과학·천문·영수증 키워드를 비교해 후보를 제안합니다. 이는 훈련된 분류기의 정확도 수치가 아닌 규칙 점수입니다. 로컬 AI를 선택하면 기존에 설치한 Ollama 모델에 본문 일부를 전달해 허용된 상대 폴더 중 하나를 제안받습니다. 모델의 confidence는 자가 평가이며 정확도 측정치가 아닙니다. 낮은 점수·허용 범위 밖 경로·잘못된 JSON은 채택하지 않습니다. 직접 지정한 목적지와 개인 규칙이 먼저 적용되며 일반 코드·데이터·자막의 종류별 목적지는 내용 제안으로 자동 대체하지 않습니다.

기본 AI 주소는 `http://127.0.0.1:11434`입니다. `--ai-url`은 인증 정보·추가 경로 없는 루프백 HTTP 주소만 허용하고 리디렉션하지 않습니다. 모델은 자동 다운로드하거나 임의로 선택하지 않습니다. 연결/응답 실패 후 이번 분석의 추가 AI 요청을 중단하고 실패와 대체 분류를 표시합니다. 화면의 ‘모델 목록 읽기’로 설치된 모델을 고릅니다.

본문·OCR 결과는 미리보기의 발췌·근거로 표시하고 프로필에 저장하지 않습니다. 계획·실행 기록에는 본문 인용 대신 일반적인 분류 근거를 저장합니다. 원격 AI API로 문서를 전송하지 않습니다. 선택한 로컬 AI 서버의 자체 로그 설정은 별개입니다. 읽은 파일의 해시를 계획에 결합해 내용 분석 후 파일이 바뀌면 실행 직전 거부할 수 있게 합니다.

## 촬영일과 유사 사진

```sh
afo preview "/작업/폴더" --photo-dates month
afo preview "/작업/폴더" --similar-photos --similar-threshold 6
```

촬영일은 EXIF `DateTimeOriginal`에 저장된 달력 날짜를 사용합니다. 시간대가 없으면 UTC로 변환하지 않으며 파일 수정일·파일 생성일·추정 날짜로 대체하지 않습니다. `year`는 `이미지/YYYY`, `month`는 `이미지/YYYY-MM`을 제안합니다. 개인 규칙이 없고 사진 촬영일과 본문 제안이 함께 있으면 선택한 촬영일 기준을 먼저 사용합니다.

유사 사진은 OS가 읽은 첫 이미지/프레임을 축소해 dHash·평균 밝기 해시와 종횡비·색을 비교합니다. 정보가 거의 없는 단색 이미지는 제외합니다. BK-tree로 비교 후보를 줄입니다. 크기·압축·밝기의 일부 변화에 대응하지만 모든 회전·크롭·편집을 찾는다는 보장은 없습니다. 후보는 축소본과 차이 값으로 수동 비교하며 **정확한 중복 삭제 목록에 넣지 않습니다**. SHA-256으로 내용이 같은 파일을 확인하는 기존 삭제 경로와 구분합니다.

JPEG·PNG·GIF·BMP·TIFF 등이 기본 대상이며 HEIC/HEIF/AVIF·RAW 등은 OS 코덱과 해당 파일의 메타데이터 지원에 따라 달라집니다. `formats`의 이미지 목록은 모든 OS에서 모든 변형을 해독했다는 보장이 아닙니다. 실제 결과와 실패 이유를 확인합니다.

## 처리 한도와 취소

한 번의 추가 분석에서 문서 100개, 사진 300개, 로컬 AI 20개, 유사 후보 200쌍까지 처리합니다. 파일당 읽기는 20 MiB, 압축 문서는 전체 해제 크기 32 MiB·선택한 XML 한 항목 8 MiB·항목 2000개, 텍스트는 최대 20만 코드 단위입니다. PDF 본문은 12페이지, OCR은 최대 6페이지, 사진은 80 MP 한도입니다. 한도·미지원·실패·일부 추출을 표시하고 남은 파일을 모두 해독했다고 표시하지 않습니다.

해독기는 별도 작업 스레드에서 실행하고 V8 힙·시간 한도를 둡니다. 이는 OS 권한 샌드박스나 전체 프로세스 메모리 상한을 뜻하지 않습니다. OS 도구에는 검증한 파일 핸들에서 읽은 소유 임시 복사본을 전달합니다. 임시 파일·해독기·OCR 프로세스는 해당 분석의 종료/취소 때 정리합니다. 화면의 ‘분석 취소’는 미리보기/계획 분석에만 적용하고 이미 승인해 실행 중인 파일 작업을 재시도하지 않습니다.
