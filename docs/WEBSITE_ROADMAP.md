## 공개 클라우드 전환 조건

`afo-hackathon-2026-7321`의 `(default)` Firestore(서울, freeTier=true)는 존재한다. 배포된 Security Rules는 기존 v1이며 현재 main의 v2와 다르다. 이 확인은 DB 목록·현재 release와 소스의 읽기만 수행한 결과다.

공개 빌드의 `VITE_AFO_CLOUD_RULES`는 기본 비활성이다. v2는 불완전한 규칙 게시를 차단하고 삭제 후에도 버전 번호를 보존하며 자식 문서 이름을 `revision_id`로 변경한다. 기존 v1 자료가 있다면 이관 없이 읽을 수 없다. 현재 v1 자료 개수 확인은 API 400으로 미검증이며 같은 실패 경로는 더 반복하지 않는다.

따라서 기존 자료 확인/필요 시 별도 이관 → 정확한 프로젝트의 v2 규칙 배포 승인 → 배포 후 readback → 합성 계정으로 UI 저장·재조회·계정 분리·서버 문서 확인 → 공개 빌드 활성화 순서가 필요하다. 기존 자료 삭제나 형식 변경은 이번에 실행하지 않는다. Google OAuth 활성화는 다른 채팅의 미결 설정이며 이 기능과 별도다.

## 경계

웹 규칙 JSON은 휴대 가능한 규칙 계약이며 CLI의 참고 근거·루트 권한을 담은 로컬 프로필과 다르다. CLI 자동 적용·파일 변경 승인을 뜻하지 않는다. 샘플 체험은 기존 고정 샘플이며 규칙 화면의 사용자 규칙으로 실제 파일을 분류했다고 표시하지 않는다.

구현·단위 검증·Emulator·실제 클라우드·실물 기기를 각각 보고한다. 마우스/키보드/기존 탭을 조작하지 않고 별도 headless Chromium에서 테스트한다. Browser plugin/skill이 제공되지 않아 프로젝트 Playwright를 사용한다.
