# CLI 우선 개발과 GUI 확장

2026-10-26 사용자 결정: CLI를 먼저 사용할 수 있게 만들고 이후 GUI로 확장합니다. GUI 프레임워크와 제공일은 아직 정하지 않았습니다.

## 공용 코어와 인터페이스 경계

```text
CLI 인수·TTY 입력 → CLI 어댑터 ┐
                             ├→ 공용 계약·서비스 → 분류 엔진·파일 실행 계층
GUI 버튼·폼 입력 → GUI 어댑터 ┘
```

- `packages/contracts`: 파일·규칙·계획·결과와 후속 승인 계약의 단일 기준
- `packages/engine`: 기본/개인화 분류, 중복 후보, 충돌 처리와 계획
- `packages/filesystem`: OS 읽기와 후속 루트 제한·실행·저널·복구
- `apps/cli`: 인수·TTY 확인과 한국어/JSON 출력. 현재 읽기 전용만 구현
- `apps/desktop` 또는 `apps/web`: 후속 GUI. 연결 방식은 선택 후 구현

GUI는 CLI의 한국어 출력이나 shell 문자열을 파싱하지 않습니다. 공용 서비스의 구조화된 요청·응답을 사용하며 CLI와 같은 승인·경로·파일 상태 검사를 거칩니다.
특정 프레임워크의 main 프로세스에 핵심 정책을 묶지 않습니다. 어댑터는 채널의 요청자와 입력을 확인하고 실제 실행 권위는 공용 서비스에 둡니다.

## 현재 명령

```sh
npm run build
npm run afo -- --help
npm run afo -- preview "/path/to/test-folder"
npm run afo -- suggest-rules "/path/to/reference"
npm run afo -- confirm-rules draft.afo-profile.json --select "실제규칙ID"
```

경로와 규칙 ID는 설명용입니다. 전역 `afo` 명령은 아직 등록하거나 배포하지 않았습니다.
JSON을 파일로 내보낼 때는 npm 배너가 섞이지 않도록 `node dist/apps/cli/src/index.js ...`를 직접 실행합니다.
현재 버전에는 실제 이동·삭제·자동 프로필 저장 명령이 없습니다.

## 후속 CLI 계약

#8/#10/#11/#12/#13에서 계획 확인·실행·취소·복구를 구현합니다. 명령 이름은 구현 전에 정하고 도움말에 실제 기능만 적습니다.
대화형 실행은 배치 단위로 확인하고 비대화형 실행은 승인 자료가 없으면 거부합니다. 기본 동의나 GUI 전용 우회 경로를 만들지 않습니다.
승인은 정확한 계획·항목·루트·파일 상태·삭제 모드·유효 기간에 결합합니다. 분류 규칙 확인과 파일 변경 승인은 다릅니다. CLI 인수의 `--yes`만으로 실행 권한을 만들지 않습니다.

## 순서와 검증

1. CLI에서 분석·규칙·계획·승인·실제 실행·복구를 작은 이슈로 완성합니다.
2. #14에서 Windows/macOS CLI의 실제 사용자 경로와 파일 결과를 검증합니다.
3. #15에서 CLI 배포·실행 안내와 대회가 인정하는 URL 방식을 검증합니다. URL 직접 실행 조건이 자동 충족되는 것은 아닙니다.
4. #9에서 같은 서비스에 GUI를 연결하고 클릭·입력·승인·파일 결과·재시작을 따로 검증합니다. CLI 검증이 GUI 검증을 대신하지 않습니다.

CLI는 GUI 설치·빌드 없이 사용할 수 있어야 합니다. GUI는 공용 계약을 기준으로 준비할 수 있지만 CLI 안정화와 GUI 실제 경로를 검증하기 전에는 제공 완료로 보고하지 않습니다.
