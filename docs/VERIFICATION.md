# AFO 검증·출시 기준

아래는 CLI와 후속 GUI의 검증 계획입니다. #19 읽기 전용 엔진과 CLI 검증은 [별도 기록](verification/READ_ONLY_ENGINE.md)에 남기며 데스크톱 UI·실제 이동/삭제·개발 하네스 검증과 구분합니다.

## 검증 수준을 나누기

| 수준 | 뜻 | 증명하지 못하는 것 |
| --- | --- | --- |
| Implemented / 구현 | 코드·설정이 존재 | 로드·실행·파일 보존 |
| Unit-verified / 단위 검증 | 특정 커밋의 독립 단위 검사가 통과 | OS API·실제 UI·배포 |
| Simulator-verified / VM·시뮬레이터 검증 | VM/CI 등의 사용자 경로를 실제 실행 | 물리 기기의 권한·파일시스템·설치 경험 |
| Physical-device-verified / 실제 하드웨어 검증 | 해당 OS 실물에서 경로·실제 파일 결과 확인 | 다른 OS·다른 버전·전체 사용자 환경 |

GitHub hosted runner의 Windows/macOS 테스트는 VM/CI 검증으로 적습니다. 실제 Mac·Windows PC에서 수행한 확인은 별도로 적습니다.
각 보고에는 commit, OS/CPU/버전, 실제 명령/수동 단계, fixture ID, 해시·경로·저널 결과, 미검증을 남깁니다.
공유 로그에는 개인 경로·파일명을 제거합니다. screenshot이나 성공 toast만으로 파일 작업 완료를 판정하지 않습니다.

## 합성 fixture와 필수 사례

테스트 시작 때 전용 temp 폴더와 baseline manifest를 만들고, 테스트 종료 때 그 폴더의 파일 개수·내용 해시·상대 경로·journal을 독립적으로 대조합니다.
fixture 이름에 개인정보를 쓰지 않으며 실제 사용자 폴더를 자동 탐색하지 않습니다. 정리도 그 실행이 만든 temp 경로로 제한합니다.

| 영역 | 반드시 확인할 사례 |
| --- | --- |
| 스캔 | 빈 폴더, 한글·공백·이모지, 깊이 제한, 접근 거부, 취소, 숨김/제외 파일, 링크·junction·하드링크 |
| 분류 | 대소문자 확장자, 확장자 없음, 중복 확장자, 애매한 파일, 이미 정리된 파일, 같은 입력의 결정성 |
| 개인화 | 참고 선택 건너뛰기, 읽기 전용 원본 보존, 근거 부족·충돌, 명시적 수정 우선, 일회성/저장 수정, 프로필 재시작·손상·초기화, 루트 겹침·변경, 규칙 버전 변경 뒤 기존 승인 거부 |
| 중복 | 같은 이름/다른 내용, 다른 이름/같은 내용, 빈 파일, 큰 파일 streaming, 스캔 중 변경, 남길 파일 삭제/변경 |
| 경계 | `..`, 경로 prefix 착각, 대상 부모 교체·링크, 루트 재선택, OS 보호 경로, 예약명·대소문자·Unicode 충돌 |
| 승인 | 승인 없음/위조/만료/재사용, 선택 일부만 승인, plan 수정, 모드 변경, 실제 승인한 대상과 결과 일치 |
| 이동 | 충돌 없는 실제 이동, 덮어쓰기 거부, 이미 존재하는 목적지, 교차 볼륨 거부, 중간 권한 오류, hash 보존 |
| 휴지통 | OS API 실제 성공/실패, 원래 경로 부재, 다른 파일 보존, 실제 휴지통 복원 가능성 확인 |
| 영구 삭제 | 합성 일반 파일만 삭제, 승인 모드 일치, 남길 원본 유지, 파일 부재 확인, 실패 후 무단 재시도 없음 |
| 복구 | 이동 직전/직후·journal commit 직전 종료, 재시작, 성공 재실행 방지, unknown 보고, 되돌릴 경로 충돌 |
| 경쟁 | 다른 앱의 파일 수정·이동·잠금, 이중 클릭, 다중 창/프로세스 같은 루트 실행, 취소 후 남은 작업 없음 |
| 공간·성능 | 논리/할당/관측 여유 공간 구분, 휴지통으로 확보량 단정 금지, 1,000파일 스캔·취소·메모리 실측 |
| 후속 GUI/IPC | 선택→미리보기→모드/개수/용량 확인→승인→결과, 키보드 동작, 진행·부분 실패, 임의 IPC·경로 거부 |

일부 OS/파일시스템 기능을 검증할 수 없으면 해당 사례를 생략 성공으로 처리하지 않고 지원 범위를 제한하거나 미검증/차단으로 남깁니다.

## 단계별 통과 조건

### M0: 타당성

- 실제 사용자 3명의 최근 경험을 기록하고 공통 문제를 정리합니다. 예상 인터뷰나 AI가 만든 응답은 결과가 아닙니다.
- 교사의 제출 방식 답변과 심사 기준 답변을 기록합니다. 10/26 기획서·Firebase 연습 과제와 최종 제품 검증을 구분합니다.
- Windows/macOS에서 별도 생성한 파일을 실제 이동·휴지통·선택 영구 삭제하는 기술검증 결과를 확보합니다. 앱 UI가 아직 없으면 엔진/OS 검사 범위로만 표시합니다.

### M1–M3: 구현과 통합

- 계약/엔진 단위 검사와 대상 OS 통합 검사에서 필요한 부정 사례가 통과해야 합니다.
- #14에서 지원하는 두 OS의 CLI로 대상 지정→분석→분류 계획→일괄 승인→이동/삭제→실제 결과를 확인합니다. GUI #9는 후속으로 같은 흐름의 화면·공용 서비스 연결을 따로 검증합니다.
- 개인화는 참고 폴더 선택→규칙 미리보기·확인→정리→재시작→새 합성 파일에 같은 규칙 적용을 두 OS에서 확인합니다. 참고한 기존 파일의 전후 경로·내용이 보존되고 삭제 후보에 들어가지 않았는지 독립적으로 대조합니다.
- 이동 되돌리기, OS 휴지통 복원, 영구 삭제의 복구 불가를 각각 CLI 실제 동작·출력과 후속 GUI에서 확인합니다.
- 중간 종료 후 재실행에서 데이터 손실·덮어쓰기·승인 확대·중복 실행이 없음을 확인합니다.
- Windows와 macOS의 실제 기기에서 각각 확인하지 못했다면 두 OS 지원이 검증됐다고 광고하지 않습니다.

### M4: 배포와 제출

- 선택한 OS·CPU와 CLI 배포 방식에 맞춰 새 환경에서 준비·설치·실행하고 핵심 경로를 다시 검증합니다.
- macOS 서명/notarization, Windows 서명/SmartScreen 제한은 현재 상태·필요한 계정·미확인 비용·사용자 영향으로 기록합니다. 승인 없이 구매하지 않습니다.
- 서명되지 않은 빌드는 공식 배포 준비 완료로 부르지 않습니다. Gatekeeper/SmartScreen을 광범위하게 끄도록 요구하지 않습니다.
- 실제 제출 URL이 제공하는 동작을 교사가 승인한 조건에 따라 검증합니다. 다운로드 링크만 있으면 직접 실행 URL이라고 부르지 않습니다.
- 별도 팀 밖 사용자 1명이 합성 파일로 목표 과제를 수행하고 발견한 불편을 수정한 뒤 해당 경로를 다시 확인합니다.
- 5분 영상은 실제 빌드·실제 파일 결과를 보여 주고 하네스 활용 방법과 미검증 범위를 설명합니다.
- 최종 URL·영상·해당 빌드 commit이 일치하고 필요한 테스트 계정이 있으면 전달합니다. 현재 설계는 로그인 없는 로컬 핵심 기능을 제안합니다.

## 검증 보고 양식

```text
Issue / PR / Commit:
Environment: OS, CPU, version, physical | VM | mock
Fixture and baseline manifest:
Steps or exact commands:
Observed files / hashes / journal / exit status:
Passed / Failed / Not run:
Verification level:
Not verified and reason:
Release blocker and unblock condition:
```

데이터 손실, 승인 밖 삭제, 덮어쓰기, 무단 루트 이탈은 출시 차단 결함입니다. 스크린샷 수정이나 성공 문구 변경으로 닫지 않습니다.
