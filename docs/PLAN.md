# AFO 개발 계획

최초 계획: 2026-10-23, 시간대 Asia/Seoul. 2026-10-26 사용자 지시로 #19 읽기 전용 엔진·CLI의 첫 구현을 진행합니다.
앱 UI·실제 이동/삭제·개발 하네스 실행·배포는 아직 하지 않았습니다. 검증 범위는 [첫 구현 기록](verification/READ_ONLY_ENGINE.md)에서 구분합니다.

## 1. 결과물과 대상

AFO(Automated File Organizer)는 파일 정리가 귀찮거나 저장공간이 부족한 사람 대신 파일을 분류·저장하고, 확인받은 파일을 삭제하는 프로그램입니다.
Windows와 macOS를 모두 지원합니다. 첫 사용자 조사는 주변 학생 3명을 대상으로 제안하되, 학생만 쓸 수 있게 제한하지 않습니다.
사용자 결정은 **CLI 우선, GUI 후속 확장**입니다. GUI 없이도 CLI에서 핵심 기능을 사용할 수 있게 하며 GUI 제공일은 아직 정하지 않았습니다.

최초 계획 단계에서 GitHub 핵심 이슈, 실행 순서, 설계 계약, 에이전트 운영 계획, 검증 기준을 정리했습니다. 이후 구현은 작은 과제로 나눠 진행하며 앱을 한 번에 구현하지 않습니다.

## 3. 핵심 기능 두 개

### 자동 분류·저장

- 선택한 폴더의 일반 파일을 훑고 문서·이미지·영상·음악·압축·설치·기타 등 기본 규칙으로 분류합니다.
- 규칙으로 분류하기 어려운 파일은 기타/검토 대상으로 남깁니다. 파일 내용의 의미를 이해했다고 표시하지 않습니다.
- 이동 위치를 미리 보여 주고 사용자가 확정한 정리안을 실행합니다. 폴더 생성과 이동은 프로그램이 합니다.
- 정리 결과와 실패 항목을 보여 주며, 이동은 조건이 맞으면 원래 경로로 되돌립니다.

자동 분류의 하위 기능으로 **내 정리 방식 참고하기**를 포함합니다([#18](https://github.com/fakeminjun7321/AFO/issues/18)).
사용자가 참고 폴더를 선택하면 구조·파일 이름·확장자에서 규칙 후보를 추출하고, 확인한 규칙만 로컬에 저장해 다음 정리에 적용합니다. 참고 선택은 건너뛸 수 있습니다.
첫 CLI 배치 승인 단계에 규칙 저장 확인을 함께 넣어 확인창을 늘리지 않습니다. 사용자가 분류를 고칠 때는 이번만 적용과 이후에도 적용을 구분하고, 저장 규칙은 끄거나 초기화할 수 있게 합니다.
규칙 충돌이나 근거가 부족한 파일은 검토 대상으로 남깁니다. 참고 폴더의 기존 파일은 이동·삭제하지 않으며 분류 습관으로 삭제 필요성을 추정하지 않습니다.
참고 전용 폴더는 읽기만 합니다. 실제 목적지는 승인한 작업 루트 안으로 제한하며, 참고한 폴더에도 새 파일을 저장하려면 그 위치를 작업 루트로 별도 지정·승인해야 합니다.

### 확인 후 삭제·공간 확보

- 내용이 같은 중복 파일과 큰 파일 등을 표시합니다. 크기·날짜만으로 불필요하다고 확정하지 않습니다.
- 중복 묶음은 원본을 남기는 안을 제안하고 사용자가 남길 항목을 바꿀 수 있습니다. 이름이 같아도 내용이 다르면 중복이 아닙니다.
- 기본 삭제는 OS 휴지통 이동입니다. 한 작업의 삭제 후보를 한 배치로 일괄 확인합니다.
- 공간을 바로 확보하려는 사용자는 **선택 파일 영구 삭제** 모드를 명시적으로 선택한 뒤 한 번의 최종 확인을 합니다. 원복 불가를 표시하고 승인한 파일만 삭제합니다.
- 휴지통 이동, 정리한 파일 용량, 관측된 디스크 여유 공간 증가를 다른 값으로 보여 줍니다. 휴지통 전체 비우기는 제공하지 않습니다.

상태 흐름: 폴더 선택 → 분석 → 분류·삭제 미리보기 → 필요한 항목만 수정 → 한 번의 배치 승인 → 실행 → 결과/이동 되돌리기.
실행 전 파일이 바뀌면 기존 승인을 무효화하고 변경된 항목만 다시 확인합니다. 편의를 위해 승인 범위를 넓히지 않습니다.

## 4. 첫 버전의 경계

대상은 사용자가 선택한 로컬 폴더 안의 일반 파일입니다. 첫 버전에서는 대상 폴더 바깥, 디스크 루트, OS 폴더, 앱·개발 프로젝트 내부, 링크·junction·다중 하드링크 파일, 클라우드 전용 placeholder 등을 보수적으로 제외합니다.
원본 내용 수정, 자동 영구 삭제, 전체 디스크 청소, 앱 제거, 캐시 일괄 청소, 클라우드 업로드, 백그라운드 상시 감시는 포함하지 않습니다.
개발 프로젝트나 앱 번들을 제외하는 규칙 자체도 양 OS에서 검증해야 합니다. 이름만 보고 재생성 가능한 캐시라고 판단하지 않습니다.

파일 내용 의미 기반 AI 분류, 확인 없이 행동을 추적하는 습관 학습, 예약 정리, 다른 디스크 이동, 클라우드 연동은 후속 기능입니다. 사용자가 확인한 분류 규칙과 명시적으로 저장한 수정은 첫 버전에 포함합니다.
범위 축소가 필요하면 두 핵심 요구를 몰래 빼지 않고 사용자와 변경 내용을 합의합니다.

## 5. 먼저 통과할 결정

1. **제출 경로**: 교사에게 CLI 실행 파일 또는 소스·Node.js 실행 방식이 인정되는지, 다운로드가 필요한 URL을 허용하는지 질문합니다. URL 직접 실행 요구를 임의로 완화하지 않습니다.
2. **실행 환경**: 실제 Windows/macOS 테스트 기기, CPU와 OS 버전, 설치 권한을 확보합니다. 아직 확보되지 않았습니다.
3. **플랫폼 기술검증**: 합성 폴더에서 선택·탐색·이동·휴지통·선택 영구 삭제·재시작 후 결과 확인을 시험하고 한계를 기록합니다.
4. CLI 방식이 인정되지 않으면 GUI/웹 제공 시점과 실제 파일 기능을 검증하고 사용자·교사와 출품 범위를 다시 정합니다. 동작하지 않는 화면으로 형식만 충족하지 않습니다.

CLI 출품 수용 여부가 미결이어도 문서·파일 계약·독립 엔진 설계는 진행할 수 있습니다. 배포 방식 확정과 출시는 미결 상태에서 진행하지 않습니다.
Firebase Hosting에 다운로드 페이지나 데모를 두는 것만으로 실제 파일 정리와 URL 직접 실행 요구가 검증된 것은 아닙니다.
