`afo update`로 설치된 AFO를 최신 정식 릴리스로 업데이트할 수 있습니다.

## 새 기능

- `afo update`: 최신 버전 확인 → 내 OS·CPU용 파일 다운로드 → SHA-256·실행 버전 대조 → 설치 실행 파일 교체. 이미 최신이거나 설치본이 더 새 버전이면 유지합니다.
- `afo help`는 자주 쓰는 명령, `afo help --all`은 전체 명령과 옵션을 보여 줍니다.
- main 변경 시 버전과 태그를 준비하고, 테스트·빌드·3개 대상의 설치 및 자체 업데이트 검증을 통과한 뒤 정식 릴리스를 자동 게시합니다. 명시적 버전 인상이 없으면 패치 버전을 올립니다.

## 설치와 업데이트

이전 공식 릴리스(v0.3.0 이하)에는 `update` 명령이 없으므로 설치 명령을 한 번 다시 실행합니다.

macOS:

```sh
curl -fsSL https://raw.githubusercontent.com/fakeminjun7321/AFO/main/install.sh | sh
```

Windows PowerShell:

```powershell
irm https://raw.githubusercontent.com/fakeminjun7321/AFO/main/install.ps1 | iex
```

v0.4.0 이상 또는 `update` 명령을 포함한 로컬 빌드는 다음을 사용합니다.

```sh
afo update
afo --version
```

규칙·정리 계획·실행 기록·PATH·오른쪽 클릭 메뉴는 업데이트로 변경하지 않습니다. 소스 실행본은 `git pull` → `npm ci --ignore-scripts` → `npm run build`를 사용합니다.

## 배포 파일과 검증 범위

- macOS Apple Silicon: `afo-darwin-arm64.tar.gz`
- macOS Intel: `afo-darwin-x64.tar.gz`
- Windows x64 (Arm에서는 x64 에뮬레이션): `afo-win-x64.zip`
- 무결성 대조: `SHA256SUMS`

릴리스 파이프라인은 세 대상의 VM/CI에서 설치·자체 업데이트·최신 버전 건너뛰기·잘못된 체크섬에서 원본 보존을 검사합니다. 별도로 macOS arm64 실물의 합성 설치본에서 확인합니다. CI 검증은 Windows·Intel Mac 실물의 검증을 대신하지 않습니다.

macOS 실행 파일은 ad-hoc 서명이며 개발자 배포 서명·공증은 없습니다. Windows 실행 파일도 배포 서명이 없으므로 Gatekeeper·SmartScreen·백신 정책에 따른 제한이 있을 수 있습니다. 이번 릴리스는 파일 정리·중복 탐지 알고리즘을 변경하지 않습니다.
